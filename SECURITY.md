# Security Policy

## Reporting a vulnerability

Do not include API keys, bearer tokens, saved credential files, confidential searches, or private X results in an issue, discussion, screenshot, or email.

Report a suspected SignalDesk vulnerability through GitHub's private vulnerability reporting form:

https://github.com/rjhllc/signaldesk/security/advisories/new

Include only the minimum information required to reproduce the problem. Redact credentials, personal information, customer information, searches, posts, local paths, and machine identifiers.

## Supported releases

Only the latest published SignalDesk release receives security fixes. Update to the newest release before reporting a problem that may already be resolved.

## Scope

Security reports may cover:

- Local credential storage or disclosure
- Desktop sandbox or navigation boundaries
- Local backend exposure
- Release integrity and update behavior
- Prompt-injection handling in optional AI review

Questions about X or an LLM provider's own platform should be reported directly to that provider.
