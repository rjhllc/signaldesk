## What SignalDesk does

SignalDesk turns a live X API search into a structured research report. It keeps the original result set intact, supports precise native X filters, and can create separate AI-ranked or AI-filtered views with conversational follow-ups after results are retrieved.

SignalDesk is a hosted web application. There is nothing to install and no SignalDesk account.

| Research workflow | Browser control | Evidence |
|---|---|---|
| Live X searches, advanced operators, sentiment summaries, CSV export | Encrypted browser credential vault, encrypted saved searches, no telemetry | Exact query previews, request diagnostics, original and closable AI result tabs |

### Highlights

- Search live X data by topic, phrase, handle, entity, URL, engagement, location, or conversation reference.
- Preserve an **Original** result tab while each AI review or follow-up opens a separate, closable tab.
- Follow up with corrections, sort every result view, and restore a recently closed AI tab with **Ctrl+Z** or **Cmd+Z**.
- Show each AI processing stage, instruction conversation, and configured model.
- Export the currently selected result view to CSV.
- Receive the current application automatically on the next visit after a production deployment.

## Use SignalDesk

Open [app.signaldesk.run](https://app.signaldesk.run).

### Required: X API Bearer Token

Create an app in the [X Developer Portal](https://developer.x.com/en/portal/dashboard), copy its Bearer Token, and paste it into SignalDesk's Credentials window.

### Optional: AI review

Choose **OpenAI** or **Anthropic**, paste that provider's API key, and select a model. AI review is available only after an X search returns posts. X, OpenAI, and Anthropic may require separate paid API access; SignalDesk does not receive those payments.

## Credential and data boundary

Credentials and saved searches persist in an encrypted IndexedDB vault scoped to `app.signaldesk.run` in the current browser profile. A non-extractable AES-GCM device key is generated by Web Crypto and stored separately in the same browser database.

“Saved locally” describes storage at rest, not the full request path:

- The browser decrypts the X token only when a search is requested and sends it over HTTPS to the SignalDesk relay.
- The relay holds the token and search data in process memory for that request, forwards the request to X, and does not persist them.
- Optional AI review follows the same path with the selected provider key and the posts being reviewed.
- Provider credentials are never configured as server environment variables and are never shared between users.
- Search results remain in browser memory. CSV data is created locally only when the user exports it.
- Clearing site data or selecting **Forget this browser** deletes the vault. Private-browsing storage may disappear when that session ends.

Browser encryption protects stored data from casual inspection of browser files. It cannot protect an unlocked browser from a malicious extension, compromised device, or future same-origin script compromise. SignalDesk serves no third-party scripts and enforces a restrictive Content Security Policy to reduce that risk.

See [PRIVACY.md](PRIVACY.md) for the complete data-flow disclosure.

## Development

The query engine and local development server use only the Python standard library. Production runs the same query engine inside a Cloudflare Python Worker; Cloudflare currently labels Python Workers as beta.

```bash
npm ci
uv sync --locked
python3 -m unittest -v test_backend.py
python3 backend.py
```

Then open `http://127.0.0.1:4173`. Localhost is treated as a secure browser context, so Web Crypto and IndexedDB remain available during development.

To exercise the production runtime locally instead:

```bash
npm run dev
```

Wrangler serves the application at `http://127.0.0.1:8787`.

## Deployment

Every push to `main` runs [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml):

1. Run the query-engine contracts and browser-script syntax checks.
2. Deploy the informative site at `signaldesk.run` with Cloudflare Workers Assets.
3. Deploy the application, same-origin relay, and browser assets at `app.signaldesk.run` as a Cloudflare Python Worker.

The `production` GitHub environment requires two secrets:

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN`, created from Cloudflare's **Edit Cloudflare Workers** template and restricted to the SignalDesk account and `signaldesk.run` zone.

The custom-domain routes in `wrangler.site.jsonc` and `wrangler.jsonc` let Cloudflare create and maintain DNS records and TLS certificates. There is no VPS, SSH key, server-side provider credential, or manually managed reverse proxy.

An authenticated maintainer can deploy both Workers manually with:

```bash
npm run deploy
```

User provider credentials remain request-scoped and must never be configured as Worker secrets or build variables.
